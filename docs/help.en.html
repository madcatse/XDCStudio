What the app does

XDC Studio prepares modern video for playback on IBM PC/XT and compatible 8088 computers running DOS. Choose an MP4, MKV, WebM or another file supported by FFmpeg and produce an XDV for the original XDC_PLAY player.

The app resizes the picture, selects colours and dither patterns, prepares audio and compiles video-memory updates within the limits of an 8088. Windows x64 handles preparation; the vintage PC only needs the result and the DOS player. Frames and audio stream through RAM, without DOSBox or intermediate BMP/WAV files.

Use Help at the bottom right or press F1. These pages work offline; only external author links need internet access. The page follows the interface language.

Quick start

  1. Extract the entire portable archive and run XdcConverter.exe.
  2. Use Browse to select a video, then choose an output XDV. Save as selects the destination; conversion starts separately.
  3. Select the profile for your video card and monitor connection. Seek to a representative moment with the slider below the preview, then adjust the picture.
  4. For a first trial, set a short length such as 10 seconds and click Convert to XDV.
  5. Watch the result in the player that opens. Set length back to 0 for the whole video. Copy the XDV, generated BAT and XDC_PLAY.EXE to the DOS computer and run the BAT.

A starting point for Composite: NTSC / early CGA, 160 × 200, 30 FPS, Bayer 8×8, gamma 1, saturation 100%, dither strength 100%, stability 50%, 150 KiB/s, integrity 75%, audio 22050 Hz. Adjust the data rate to the actual drive.

The original XDC player needs a Sound Blaster-compatible card for audio. See the XDC website for DOS player requirements and capabilities.

Conversion settings

These settings change the finished XDV. The preview updates automatically after edits; there is no refresh button.

OptionPurpose and trade-off
Source video / Output XDVInput file and output destination. An XDV name must have 1–8 letters A–Z, digits or _, for example MOVIE.XDV. DOS device names such as CON and NUL are reserved. Windows folder paths may contain spaces and Cyrillic characters.
ResolutionComposite offers 160 × 200 and 160 × 100. The latter reduces detail and the amount of data to update, which can help busy scenes. It writes only the odd CGA scanlines. B&W and Tandy have fixed resolutions.
CGA colourNTSC / early CGA and NTSC / late CGA select colours and patterns for the corresponding card circuitry. old mode restores the previous matching method for comparison. Composite only. Selecting an NTSC target also aligns the preview model with it.
Frames per second15, 23.976, 24, 25, 29.97, 30, 50, 59.94 or 60 FPS. Start at 30. More frames leave fewer 8088 cycles and bytes per frame at the same data rate. Lower FPS may allow more complete pictures, at the cost of less fluid motion.
DitheringBayer 8×8 is the default regular pattern with more mixture levels. Bayer 4×4 repeats over a smaller area with fewer levels. Blue noise uses a less regular static 8×8 mask: a different texture, not necessarily a better result. None uses solid colours. All masks stay fixed in screen coordinates, without random changes between frames.
Gamma0.30–3.00; 1.00 leaves the image unchanged. Values above 1 brighten midtones; values below 1 darken them. This can reveal shadow detail before colour matching.
Saturation, %0–200%; 100% preserves the original saturation. At 0% the source becomes grayscale before palette matching; this does not guarantee neutral gray on a composite display. Disabled for monochrome CGA.
Dither strength, %0–100%; limits colour mixing. 0% uses solid colours; 100% allows full mixing. Lower strength makes NTSC matching choose a new mixture within that limit. Disabled when dithering is None.
Stability, %0–100%, default 50%. Retains nearly equivalent regions between frames and prioritizes useful updates according to their 8088 cost. 0% switches the mechanism off completely. High values can leave motion trails. Applies only to Composite with NTSC matching and noticeably increases conversion time. Inspect the effect in the finished XDV: a still preview has no frame history.
Reset colour adjustmentsRestores gamma 1.00, saturation 100% and dither strength 100%. It leaves the selected mask, stability and CGA model unchanged.
Aspect ratioFit keeps the whole image with borders. Crop fills the display and trims edges. Stretch fills the display with possible shape distortion. The target screen is 4:3, even though logical pixels need not be square.
Data rate, KiB/s30–500, default 150. The drive-read budget includes video, audio and sector padding. Higher values can allow fuller updates and larger files. Choose a rate the actual drive can sustain; increasing it does not remove the CPU limit.
Frame integrity, %0–100, default 75. The completed proportion of pending updates required before the encoder can accept a new target. Higher values favour completing an older picture; lower values favour newer frames but may leave incomplete areas. This is not a JPEG-style quality percentage. The NTSC stabilizer can release the old target early when it detects a large scene change.
Audio trackSelect one input track or No audio / silence, which writes silence into the XDV. Sound is converted to mono 8-bit PCM; you do not need to prepare a WAV.
Audio rate, Hz11025, 16000, 22050 or 32000. Higher rates preserve more audio detail but use a larger share of the total data budget. The default is 22050 Hz.
Start / Length, secondsStart sets the export position; length limits the excerpt. Length 0 means to the end. The preview slider chooses only a viewing position and does not change this export range.
DeinterlaceRemoves comb-like motion edges from interlaced sources. Leave it off for ordinary progressive video.

Preview and NTSC

The slider below the picture selects a source moment. With Compare with source enabled, the source is on the left and the prepared frame on the right. Drag the divider; after clicking the picture, arrow keys move it, Home shows the entire result and End the entire source.

NTSC… (or Palette…) in the main window and player opens the composite monitor settings:

  • Model: early IBM CGA, late IBM CGA, or the XDC palette without signal modelling.
  • Hue: −45…+45°, simulating colour-phase adjustment.
  • Chroma: 0–200%, saturation of the displayed signal.
  • Reset: early CGA, hue 0°, chroma 100%. Close dismisses the window; settings take effect immediately.

Monitor settings affect viewing only. The main form's CGA colour selector controls the XDV colour target. Matching uses that card with hue 0° and chroma 100%. XDV does not identify early or late CGA, so choose the appropriate viewing model manually when opening another file.

The main preview shows a prepared frame before interframe encoding limits. The finished XDV may differ because of stabilization and constrained updates. The NTSC model approximates dot blending and colour; an actual monitor may look different.

Русский / English above the preview switches the app language. The Log records progress and errors; the status line and progress bar below show the current operation.

Playing the finished XDV

The player opens automatically after conversion. Play XDV reopens it; you can also drop an existing XDV onto the main window. Open output folder shows the generated files.

  • ▶ plays, Ⅱ pauses, and ■ stops and returns to the beginning.
  • The seek slider selects a frame and pauses playback; press ▶ to continue. Left/Right keys step through frames when focus is outside the volume and part-selection controls.
  • Space toggles play/pause when focus is not on a button or control that uses that key.
  • The slider on the right sets volume from 0–100%. Mute temporarily silences audio without changing the level. Player volume does not alter the exported XDV.
  • The list above the screen selects a part of a split video. The time display refers to the current part.

Frames and sound are read directly from XDV. Actual incomplete frame updates are visible, but physical drive stalls and CGA snow are not modelled. Check the final result on the target PC.

Improving the result

  • Flickering pattern: start at 50% stability, compare Bayer 8×8 and 4×4, and try lower dither strength. Static blue noise changes the texture but does not always reduce flicker.
  • Trails or lagging updates: reduce stability, try lower FPS or 160 × 100, and consider lower integrity. Higher data rate helps only if both drive and CPU have spare capacity.
  • Colours differ from your monitor: check the target profile and CGA variant. NTSC… viewing adjustments do not re-encode the file. Main-form saturation and gamma do change the output.
  • Faces or shadows too dark: raise gamma slightly and check several different frames.
  • Conversion takes longer: NTSC stabilization processes the sequence. On the test PC, full MIR took about 85–93 seconds versus 4–5 seconds at 0% stability; other computers will differ.
  • Data rate too low: reduce FPS or audio sample rate, or increase the data rate within the drive's capabilities.

Files and command line

Cancel stops the current operation. Existing output prompts for overwrite and is preserved until conversion succeeds. The app writes the finished XDV and accompanying files, rather than intermediate frames. An unfinished XDV uses a .partial suffix and is removed on cancellation.

The output folder also receives a DOS BAT, XDC_PLAY.EXE, a text log and a JSON report. Long videos split every 60000 frames. Keep app and docs beside the Windows EXE: they contain dependencies and help. Language is stored in app/ui-settings.json; viewing preferences in app/monitor-settings.json.

Automating with JSON

XdcConverter.exe --convert job.json starts conversion. A small example:

{
  "Input": "C:/video/MIR.webm",
  "Output": "C:/video/MOVIE.XDV",
  "Mode": 1,
  "Dither": "bayer4",
  "TemporalStability": 50
}

Mode: 1 Composite, 2 B&W, 3 Tandy. Main setting fields: HalfHeight, Fps, Gamma, Saturation (a 0–2 multiplier), DitherStrength, TemporalStability, DiskRate, Integrity, SampleRate, Start, Duration, Deinterlace.

Dither: bayer, bayer4, blue, none. Fit: fit, crop, stretch. CompositeAlgorithm: ntsc or legacy; CompositeNewCga: true selects late CGA. Silent: true silences audio; AudioStream is the FFmpeg stream index, not the list row number. SegmentFrames: 1–60000 frames per part. Overwrite: true explicitly permits replacement without a prompt.

Run report: job.json.result.json; exit code 0 means success, 1 failure. --play FILE.XDV opens playback; --inspect FILE.XDV report.json saves file information.
